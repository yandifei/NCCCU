# 赛事预测与自动打包

运行根目录 predict.py。正式测试集预测完成后，它会把实际产出目录交给 push.py。换模型时，在 predict.py 的 model 选择新版 ConvNeXt 训练目录的 weights/best.pt。输入尺寸跟随检查点，预测目录按时间生成。历史 YOLO 提交包继续使用生成时附带的代码。

```powershell
uv run --no-sync python predict.py
```

push.py 从本次预测的 args.json 获取模型、精度、阈值和其他推理参数，再从对应训练目录的 args.json 获取训练参数和预训练权重。ZIP 写入 outputs/submission/<预测目录名>/，每次预测独立保留。验证集和冒烟预测跳过打包。

在 push.py 中配置实际 TEAM_NAME、已填写官方 XLSX 的 DECLARATION 和对应 LICENSES。默认 XLSX 路径为 outputs/合规材料/模型核验材料与数据申明清单.xlsx。缺少已填写的核验表时，脚本生成带“待核对_缺核验表”字样的 ZIP，并写入填写所需的权重 SHA-256 和推理精度。补齐后执行以下命令，保留原预测和 CSV：

```powershell
uv run --no-sync python push.py outputs/predict/<预测目录名>
```

最终包包含 code/、model/、pretrain_model/、licenses/、cost.py、核验表和 submission.csv。预测 CSV 会校验官方测试检查覆盖范围、重复记录和概率区间。包内代码由实际运行配置生成，权重使用归档相对路径。模型缓存、训练断点、原始影像和数据集 CSV 均不入包。官方最终合规 ZIP 应选线上历史最高分对应的预测目录。

## 官方复测

新版预测的 args.json 额外记录模型 SHA-256。重打包时会核对当前权重和 ZIP 内权重摘要；若 best.pt 已被后续训练覆盖，需恢复对应权重或重新预测。历史无摘要记录仍兼容，但不能通过该记录确认模型内容未变。

解压后将官方数据放入解压根目录的 datasets，保留 test.csv 和 test/<Subject_id>/<Study_id>/<Dicom_id>.jpg 的布局。根目录运行：

```powershell
python cost.py submission.csv <pictures_100> <pictures_5>
```

cost.py 读取包内 predict.py 的实际配置，复用图像读取、模型加载、前向和概率计算。5 张预热图不计时，100 张抽样图按 batch=1 串行执行三轮，从图像读取计至写出结果；同一检查的其他视图从抽样目录或官方完整测试目录补齐，并计入该次耗时。逐张核对概率误差、二值判定和排序，不一致或平均超过 100 ms 时返回非零状态。需以主办方提供的抽样和 T4 环境完成正式复测。

包内 requirements.txt 和 uv.lock 记录本地开发依赖。主办方使用 Python 3.12 和预装的 PyTorch，复测应以其指定环境验证运行兼容性与时延。
