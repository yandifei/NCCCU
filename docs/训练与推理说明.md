# ConvNeXt-Small 训练与推理

当前第四版用 `convnext_small.fb_in22k_ft_in1k` 做十类独立 sigmoid 分类，启用 FP32、较低学习率与较短余弦周期，针对第三版早期过拟合开展对照。原 YOLO 结果留作历史对照，验证集最佳 Macro-AUC 为 0.77518（224 输入）和 0.77197（512 输入）。第三版 ConvNeXt 为 0.79437。第四版继续使用 512 输入、逐图 BCE 和 Study 概率均值，完整训练收益待确认。

## 权重和环境

权重使用 timm 模型卡标注的 ImageNet-22K 预训练、ImageNet-1K 微调版本，固定 Hugging Face 修订 `fe6b358aa409414cdb522ae3d43a2c9922f7cc1b`。在仓库根目录运行：

```powershell
curl.exe -fL "https://huggingface.co/timm/convnext_small.fb_in22k_ft_in1k/resolve/fe6b358aa409414cdb522ae3d43a2c9922f7cc1b/model.safetensors" -o pretrain_model/convnext_small.fb_in22k_ft_in1k.safetensors
Get-FileHash pretrain_model/convnext_small.fb_in22k_ft_in1k.safetensors
uv sync --locked
```

SHA-256 为 `2457488bec2ffcb2061b9e3fdd63360114549615e3e35ef6dc5c5efe549cbbc9`。训练入口加载完整预训练权重，再重置为十类头。归档保留[模型卡标注的 Apache-2.0](ConvNeXt-Apache-2.0.txt)与[上游 ConvNeXt 仓库 MIT](ConvNeXt-upstream-MIT.txt)。[模型卡](https://huggingface.co/timm/convnext_small.fb_in22k_ft_in1k) · [上游仓库](https://github.com/facebookresearch/ConvNeXt)

## 开始训练

在 PyCharm 直接运行根目录 train.py，或执行 `uv run --no-sync python train.py`。默认输出目录是 `outputs/train/v4_fp32_lr3e5_512`，`resume=False`，从 ImageNet 预训练权重开始。再次从预训练权重开始时修改 name。默认参数如下：

| 项目 | 值 |
| --- | --- |
| 图像 | 保持宽高比缩放并填充到 512，RGB 按 ImageNet 均值和标准差归一化 |
| 优化 | AdamW，初始目标学习率 3e-5，1 轮预热，随后余弦衰减，lrf=0.01 |
| 批量 | 微批 8，累积 16 批，最后一组按实际样本数归一化 |
| 正则化 | 权重衰减 0.0005，分类头 Dropout 0.2，亮度扰动 ±10% |
| 轮数 | 上限 16，Macro-AUC 连续 6 轮无提升则早停 |
| 环境 | RTX 5080，FP32（amp=False），seed=0、deterministic=True，关闭 TF32，channels-last |

训练从官方 CSV 读取影像，每轮按 Study 平均概率并以 Macro-AUC 选模。训练日志、args.json、results.csv、results.png 和权重均写入同一个运行目录。默认按批解码，避免为 512 输入创建约 23 GiB 的整套磁盘缓存。

启动日志显示解析后的运行名、精度、学习率、轮数、预热、早停和实际保存目录。正式第四版应显示 `name=v4_fp32_lr3e5_512`、`精度=FP32`、`lr0=3.00e-05`、`epochs=16`、`warmup_epochs=1`、`patience=6`，以及 `GradScaler=False`、`TF32(matmul/cuDNN)=False/False`。仅修改目录名不会切换参数，已有 `outputs/train/v4` 的记录仍是第三版配置。

中断后，将 train.py 中的 model 指向该次训练的 `weights/last.pt`，并将 resume 设为 True。程序从下一轮继续，使用原训练配置并写入原目录。best.pt 是推理权重。历史 YOLO 检查点应使用旧版本代码加载。

恢复时除 device 外，入口参数不会覆盖检查点内的原配置。开启本次第四版应保持 `resume=False`，不要恢复第三版或旧 `outputs/train/v4` 的 last.pt。已完成或早停的运行不能恢复成新实验。

## 预测和提交

predict.py 默认读取 `outputs/train/v4_fp32_lr3e5_512/weights/best.pt`。尺寸从权重读取，默认 FP32 和 batch=1，以与 cost.py 的前向方式一致。正式测试集输出 14,140 条预测记录，并调用 push.py 打包。阈值初始为 0.5，可在训练完成后运行 `uv run --no-sync python tools/analyze_training.py`，仅用官方 valid 重新校准。分析入口已选择相同第四版目录与 batch=1。将确认后的共同阈值填入 predict.py 的 gate，再执行预测。调整 Gate 不改变提交的连续概率或 Macro-AUC。详见 [自动打包说明](赛事提交打包.md)。

```powershell
uv run --no-sync python -m unittest discover -s tests
```
