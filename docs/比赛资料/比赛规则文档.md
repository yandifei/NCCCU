## 5. 赛题背景

胸部 X 光片（Chest X-ray）是筛查和辅助诊断多种肺部疾病最常用、最经济的影像学检查手段。然而，胸片解读高度依赖放射科医生经验，存在**主观性强、耗时耗力**等问题。近年智能影像分析在医学影像领域展现巨大潜力，可辅助医生进行高效、准确的疾病筛查。

本次比赛鼓励参赛者开发**高精度、高鲁棒性的多标签分类算法**，进行多目标胸部病变的检测与分类，以推动计算机辅助诊断（CAD）系统的发展。

> 注意：赛题文案中「检测与分类」为医学语境下的泛称；**实际评分只考察分类**——标注、提交格式与指标均为「检查级 × 10 类概率」，不提供任何边界框/掩码标注。详见 [赛题技术分析：YOLO 任务类型判断](赛题技术分析-YOLO任务类型判断.md)。

---

## 6. 任务描述

1. 任务类型：**多标签胸部疾病分类**（multi-label chest disease classification）。
2. 与单标签分类的区别：一张胸片可同时存在**多种异常征象或疾病**，模型需对 10 个类别**各自独立**输出患病概率，而非只选一个类。
3. 要求：
   - 基于官方标准化胸片训练集，学习影像特征与多组标签之间的映射；
   - 对测试集每张片做推断，输出其可能包含的**所有类别概率**；
   - 在**样本不均衡、标签共现、类间相似性高**的条件下保持高鲁棒性与泛化能力。

| 子集   | 检查数（study） | 标注                       | 用途                         |
| ------ | --------------- | -------------------------- | ---------------------------- |
| 训练集 | **18 513**      | 完整多标签标注             | 模型训练                     |

### 7.2 数据内容与格式

- 图片格式：**JPG / PNG**
- 图片尺寸：**不固定**（不同拍摄设备存在差异）
- 图片命名与目录：按「患者 → 检查 → 图像」三级组织，结构如下：

```text
images/
├── subject_00001/                  # 单个患者的唯一 id
│   ├── study_00001/                # 单个研究的唯一 id
│   │   ├── image_000001.jpg        # image_000001 为图像 id
│   │   └── image_000002.jpg
│   ├── study_00002/
│   │   ├── image_000003.jpg
│   │   └── image_000004.jpg
│   └── ......
└── ......
```

![数据目录结构示意](assets/数据目录结构.png)

> 一个 `Study_id` 可能包含**一张或多张**胸片（如不同体位/不同时间点），这点对「图像级 → 检查级」聚合很关键。

### 7.3 字段说明

| 字段                 | 含义                                                                     |
| -------------------- | ------------------------------------------------------------------------ |
| `Subject_id`         | 单个患者的唯一 id                                                        |
| `Study_id`           | 单个检查的唯一 id，可能包含一张或多张胸部 X 光片                         |
| `Predict_class`      | 患病类别 id                                                              |
| `ViewPosition`       | X 射线穿透身体的方向（X 光机投射视角）                                   |
| `PatientOrientation` | 患者检查时的身体姿势                                                     |
| `Rows`               | 图像高度                                                                 |
| `Columns`            | 图像宽度                                                                 |
| `Support Devices`    | 是否存在任何类型的医疗支持设备：1=有，0=无，-1=不确定，None=报告中未提及 |

### 7.4 类别标签（共 10 类，id 1–10）

| 类别 id | 中文名称     | 英文名称                   |
| ------- | ------------ | -------------------------- |
| 1       | 纵隔心影增大 | Enlarged Cardiomediastinum |
| 2       | 气胸         | Pneumothorax               |
| 3       | 肺部实变     | Consolidation              |
| 4       | 肺炎         | Pneumonia                  |
| 5       | 肺水肿       | Edema                      |
| 6       | 心影扩大     | Cardiomegaly               |
| 7       | 肺不张       | Atelectasis                |
| 8       | 肺部阴影     | Lung Opacity               |
| 9       | 胸腔积液     | Pleural Effusion           |
| 10      | 无异常发现   | No Finding                 |

![类别标签映射表](assets/类别标签映射.png)

**标注规则**：每个类别只有在相关检查报告中**被正面提及**且**出现在对应图像中**时才会被标记。也就是说：
- 标签是**多标签（可共现）**，不是互斥的单标签；
- 「无异常发现（No Finding）」也是一个独立类别；
- 报告「未提及」≠ 阴性，标注口径以主办方给定标注为准，不要自行按报告文本重标。

## 8. 评价标准

### 8.1 提交次数限制

- **每日最多 2 次提交**。
- 全程仅 **1 次撤销**机会（见 §9.3）。

### 8.2 评估指标

| 指标                        | 作用                   | 说明                                     |
| --------------------------- | ---------------------- | ---------------------------------------- |
| **宏平均 AUC（Macro-AUC）** | **主指标（排名依据）** | 先对每个类别分别算 AUC，再对 10 类取平均 |
| 宏平均 F1（Macro-F1）       | 副指标                 | 仅当主指标完全相等时用于二次排序         |

- 排名方法：**优先按 Macro-AUC**；当且仅当主指标相等，才用 Macro-F1 二次排序。
- Macro-AUC 只看概率排序、与阈值无关；Macro-F1 依赖阈值判定（`submission.csv` 的 `Gate` 列）。

### 8.3 评分细则（据《补充说明》第十条）

- 主指标后台按 0–1 小数计算，**保留 4 位小数**（第 5 位四舍五入）；
- 成绩公布页将后台值 ×100 转为**百分制**展示，保留 2 位小数（例：0.8108 → 81.08）；
- 排序以公布页展示的百分制数值为准（即按后台 4 位小数值换算后比较）；
- 副指标仅后台计算、不展示；若副指标仍完全相等，则**按提交时间先后**（较早者优先）。

## 10. 官方规则要点（《比赛参赛规则》11 条 + 补充说明）

> 完整原文见 [比赛参赛规则（官方PDF转写）](比赛参赛规则（官方PDF转写）.md)；补充口径见 [参赛规则补充说明（官方PDF转写）](参赛规则补充说明（官方PDF转写）.md)。以下为备赛必须掌握的红线。

### 10.1 预训练模型（第 1 条）

- **仅允许非医学领域开源预训练权重**，以**预训练主数据集**为判定依据：
  - 允许：ImageNet、COCO、LAION 等通用自然图像 / 公开文本数据预训练；
  - 禁止：预训练主数据集为**医学影像、医学文献或医学数据库**的权重——明确点名 **RETFound 及其衍生（如 RETFound-LoRA）**、眼底/病理/放射/超声等医学影像预训练权重；
  - 通用数据集中**混入少量医学内容**不视为医学预训练（以 model card / 官方论文披露的主数据集为准）。
- 「开源」= 权重公开可下载 + 许可证允许本次赛事使用（含**再分发权利**）；**NC（非商业）许可证、gated（需审批授权）模型不予接受**。
- 限制范围限于**视觉骨干网络**及其同来源公开权重。
- **禁止**对预训练权重用医学数据集做二次预训练或自监督续训（《规则》第 1 条原文为「任何医学数据集」）；《补充说明》明确该禁止针对**外部/非官方**医学数据。
- 赛后须提交：模型名称、权重公开链接、许可证全文、上游训练数据说明（model card/论文）、权重文件 SHA-256。
- 补充说明：**允许用官方训练集做自监督预训练/续训**（不引入外部医学数据和测试集）；对外部通用无标签数据（ImageNet/COCO/LAION）自监督也允许，但须申报且不得用于模型选择/调参/早停；**知识蒸馏允许**，但教师模型同样必须是非医学开源权重（教师不参与推理则不计入 500MB，但哈希与许可证仍须申报）。

### 10.2 训练数据（第 2 条）

- 允许：用**赛方提供的训练数据**对合规预训练权重做有监督微调；
- 禁止：任何**非赛方提供的医学数据**（外部医学数据集、医学文献衍生数据、医院私有数据）用于预训练、续训、自监督、伪标签或微调。
- 补充说明：**是否带标签不改变判定**——外部无标签医学图像同样禁止。

### 10.3 验证集（第 3 条）

- 验证集是否并入训练由选手自主决定；
- **一旦并入训练，不得再用于早停、checkpoint 选择、阈值/超参数调整**（这些选择须在并入前完成）。

### 10.4 数据增强（第 4 条）

- 训练阶段允许任何**不引入测试集信息**的增强：几何变换、像素变换、遮挡类、Mixup/CutMix、过采样/欠采样、类别加权损失等；
- 允许增强结果**离线预生成落盘**；
- **推理时关闭所有随机增强算子**，随机参数不进入推理。

### 10.5 测试集（第 5 条）

- 测试集图像（无论是否带标签）**不得以任何形式**进入预训练、微调、自监督或伪标签生成；
- 不得用测试集估计归一化统计量、类别先验、分割阈值/置信度阈值/NMS 参数，不得用于 checkpoint 选择或任何参数拟合；
- 仅可在本地用测试图**验证提交脚本可运行**，不得据此改模型/后处理。

### 10.6 测试阶段推理（第 6 条）

- 只允许**固定参数前向推理**，所有权重、BN/LN/GN 统计量与仿射参数、dropout、可学习后处理参数全部冻结；
- 禁止梯度更新、测试时训练（TTT）、测试集统计量拟合、跨样本自适应；
- 允许**每图独立、确定性**的预处理（如基于该图自身均值方差归一化）；禁止跨多张测试图汇总统计量；
- 含 BN 模型须 **eval 模式**、用训练集统计量推理；
- 阈值、NMS、置信度等后处理参数须在训练/验证阶段固定；
- **允许 TTA**（翻转/多裁剪多次前向取平均）与**多模型集成**（固定模型投票/平均）；
- 补充说明：「患者平滑」若只是对**同一患者**的多张测试图输出做确定性聚合（均值/多数投票），不拟合参数、不用测试集统计量/标签，则属于允许的推理后处理。

### 10.7 推理时间（第 7 条）

- 口径：主办方指定硬件上，对固定 **100 张**样本按 **batch=1 串行**，从读图到写出结果的**端到端**耗时（含预处理+后处理）；模型加载、初始化、预热不计入；
- 5 张预热图；连续 3 轮，先每张取 3 轮均值，再 100 张取平均；
- 允许 FP16/INT8 等加速，但须在提交声明中注明；
- **单张平均上限 100 ms**，以主办方复测为准；
- **`cost.py` 必须导入并调用与 `predict.py` 相同的推理函数/模型加载逻辑**，且结果须与 `submission.csv` 一致；执行命令参考：

```bash
python cost.py <submission.csv 文件地址> <pictures_100> <pictures_5>
```

- 一致性核验：100 张逐张比对，样本级结果（`Pred_Label/Gate` 二值判定及概率排序）必须**完全一致**（不一致张数须为 0）；`|Δp| ≤ 1e-3` 且不改变判定与排序的浮点波动不计为不一致；
- 超时处置（补充说明第九条）：
  - ≤100 ms：正常认定；
  - 100–150 ms：成绩暂不认定，允许**限期优化后复测一次**（只可优化推理实现，不得换权重或改变预测结果）；
  - >150 ms：不再复测，相关成绩**直接不予认定**。

### 10.8 模型文件大小（第 8 条）

- 口径：**最终测试集推理实际加载**的模型权重（多模型融合按去重后总和）+ 必要配套文件，**解压后合计 ≤ 500 MB**；
- 计入：模型权重、推理用 config、归一化统计量、类别表、量化/编译后的引擎文件；
- 不计入：项目代码、依赖运行环境、训练产物、未被推理调用的其他格式权重；多格式并存时只计最终被调用的一份；
- 文件清单须随提交包提供，由主办方解压实测。

### 10.9 环境与材料声明（第 10 条）

- 提交须保证**结果可复现**；
- 第 1 条要求的开源模型材料须随提交一并提供。

### 10.10 违规认定与处罚（第 11 条）
