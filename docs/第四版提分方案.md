## 高精度训练

当前入口设置 `amp=False` 可关闭 autocast 与 GradScaler。保留 `deterministic=True` 时，项目还会关闭 matmul 和 cuDNN 的 TF32。模型和输入沿用 FP32。当前验证与默认预测已经使用 FP32，预测配置为 `quantize=32`。

AMP 按算子选择数值类型，BCEWithLogits 等算子可在 FP32 中计算，GradScaler 用于处理梯度缩放。完整 FP32 通常增加计算和激活内存开销，预测准确率收益须做对照确认。[PyTorch AMP 文档](https://docs.pytorch.org/docs/2.15/amp.html) · [PyTorch AMP 使用示例](https://docs.pytorch.org/tutorials/recipes/recipes/amp_recipe.html)

精度实验从同一份 ImageNet safetensors 新建训练，使用新的 name 和 `resume=False`。当前恢复代码沿用 last.pt 中的原始配置，只允许覆盖 device，因此在 AMP 续训入口修改 amp 不会切换精度。已早停的第三版也不能直接用 resume 开启新实验。

采用 batch=8、nbs=128。若运行环境变化造成 FP32 显存不足，可改成 batch=4、nbs=128，同时将 AMP 对照也改为 batch=4，避免把微批变化混入精度结论。小规模入口验证与完整训练的显存、耗时应分别记录。

## 首轮候选配置与对照顺序

采用现有 ConvNeXt-Small ImageNet 权重与 512 全图填充。首轮主候选如下，均为当前入口支持的参数。

| 参数 | 第三版 | 第四版主候选 |
| --- | --- | --- |
| amp | True | False |
| deterministic | True | True |
| batch / nbs | 8 / 128 | 8 / 128，显存不足时采用上述配对调整 |
| lr0 | 1e-4 | 3e-5 |
| epochs | 40 | 16 |
| warmup_epochs | 3 | 1 |
| lrf | 0.01 | 0.01 |
| patience | 12 | 6 |
| weight_decay | 0.0005 | 0.0005 |
| dropout / brightness | 0.2 / 0.1 | 0.2 / 0.1 |
| workers / seed | 6 / 0 | 6 / 0 |

降低微调学习率并缩短余弦周期，让学习率在实际有效训练阶段更早下降。patience 控制训练成本。上述值是待验证起点，并非已确认最优参数。

如需拆解完整候选的收益来源，可按以下顺序另做对照，给每次运行独立目录，所有实验均从同一 ImageNet 初始化权重开始。

1. `v4_precision_fp32` 只将第三版 amp 改为 False，其他配置沿用第三版，包括 40 轮调度、3 轮预热和早停。与第三版比较数值精度影响。
2. `v4_lr_fp32` 在精度实验基础上只将 lr0 改为 3e-5，观察微调强度的影响。
3. `v4_schedule_fp32` 使用上表主候选，将余弦周期改为 16 轮、预热 1 轮、patience=6，作为一组调度方案比较。改变 epochs 会改变每一步的学习率轨迹，不能把它视为单纯提前结束运行。
4. 若候选仍明显过拟合，单独比较 weight_decay=0.005 与 0.0005。选定配置再用 seed=1 复核相对第三版的改善是否稳定。若 FP32 没有稳定收益，可在相同候选配置下恢复 AMP 比较吞吐和分数。

每一步根据结果决定是否继续，避免无条件展开整个参数网格。以各运行的最佳 Study Macro-AUC 为主要选择依据，结合逐类 AUC、验证 BCE；进一步分析时可增加患者分组的配对 bootstrap 差值区间。bootstrap 仅估计当前验证样本的差异不确定性，反复在同一 valid 选模仍可能产生乐观偏差。Macro-AUC=1 意味着十个有效类别均实现正负样本的完美排序，无法通过指定训练参数保证达到。

## 后续结构性实验

以下功能需要代码实现，当前入口尚未提供对应配置。

1. **骨干与分类头分组微调。** 候选骨干学习率 1e-5、分类头 1e-4，bias 和归一化参数单独作为零衰减组。与统一学习率方案对照。当前调度会覆盖全部参数组的 lr，实现时须让调度乘上各组倍率，保存并恢复相同分组。
2. **Study 等权监督。** 先保留全部官方影像，对逐图损失按该检查影像数的倒数加权，并使用固定、明确的全局归一化，使各 Study 在整轮中的总权重一致。与普通逐图 BCE 对照。之后再比较完整 Study 组批、聚合多视图概率后计算一次 BCE 的方案，训练与推理使用同一聚合定义，全部视图参与。
3. **骨干正则化。** 单独尝试 drop_path_rate=0.1。目前 dropout=0.2 作用于分类头，骨干 stochastic depth 未在项目中开启。新增参数须进入配置与检查点恢复链路。
4. **类别不平衡。** 在逐类 AUC 确认薄弱类别后，将 ASL 作为独立损失候选，初始可考察 gamma_pos=0、gamma_neg=2、clip=0.05，并对照 BCE。类别统计只由官方 train 得到，最终按 Macro-AUC 判断。ASL 对正负样本采用不同的聚焦机制，其论文收益不代表本赛题一定提升。[ASL 原论文](https://arxiv.org/abs/2009.14119)

多视图融合和长尾分类有相关公开研究支持，CheXFusion 在胸片多标签任务中研究了这两条路线，支持作为候选方向。其数据和评价口径与本赛事有差异。[CheXFusion 论文](https://openaccess.thecvf.com/content/ICCV2023W/CVAMD/html/Kim_CheXFusion_Effective_Fusion_of_Multi-View_Features_Using_Transformers_for_Long-Tailed_ICCVW_2023_paper.html)

## 推理阈值与提交流程

本地赛事资料规定 Macro-AUC 为主指标，只有主指标公布值相同才比较 Macro-F1。Gate 只参与二值判定，因此调 Gate 主要用于改善副指标。完整独立概率仍写入 Probability 列。[本地评价规则](比赛资料/比赛规则文档.md) · [评分补充说明](比赛资料/参赛规则补充说明.md)

第三版最佳轮的 Macro-F1@0.5 为 0.24819，值得用验证概率重新估计阈值，但该数值不能直接推导最优 Gate。当前尚未生成第三版阈值分析产物，具体阈值待校准。

1. 固定最终 best.pt、输入尺寸、推理精度、batch、视图聚合与 TTA 设置。
2. 使用官方 valid 生成 Study 概率。现有 tools/analyze_training.py 已有共同阈值、逐类阈值搜索及按患者分组五折阈值交叉拟合。入口已将分析 batch 改为 1，与提交预测对齐，并默认分析本次第四版 best.pt。
3. 优先选择共同阈值。比较验证内和患者分组交叉拟合的 F1，逐类阈值若收益不稳定，采用共同阈值。交叉拟合只隔离阈值拟合，模型本身仍使用过该验证集选模。
4. 目前预测、CSV 写入和 cost.py 接收单个 gate。采用十个逐类 Gate 时须同步扩展三处接口、类别顺序及打包元数据，不能直接把阈值数组塞进现有标量参数。
5. 新模型、FP16 推理、TTA 或融合策略确定后重新校准。阈值在测试推理前固定，测试集仅用于生成提交结果。

当单模型方案稳定后，可独立比较水平翻转 TTA 和两个互补模型的固定概率平均。v3 best.pt 实际为 197,932,853 字节，两个同规模文件约 396 MB，仍须将全部推理配套文件计入 500 MB 限额。TTA 和融合增加推理耗时，须同时满足官方 T4 上 batch=1 端到端 100 ms 要求。更高输入尺寸 640 排在后续独立实验，先比较逐类 AUC 改善和代价。
