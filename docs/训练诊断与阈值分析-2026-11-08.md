# 2026-11-08 训练诊断与阈值分析

> 历史资料，对应此前的 YOLO 版本。当前入口与参数见 [ConvNeXt-Small 训练与推理](训练与推理说明.md)。

## 分析对象与结论

读取 `outputs/train/ncccu_cls/args.json`、54 轮 `results.csv`、`best.pt` 和 `last.pt`。本次实际配置为 YOLO26x-cls、224 输入、batch=128、workers=6、AdamW、lr0=0.001、epochs=1000、patience=50、严格确定性、AMP、dropout=0，随机增强关闭。nbs=64 小于实际 batch，本次每批更新一次优化器。

本次最明确的问题是过拟合。224 输入可能限制精细结构信息，但仅凭这一条训练曲线不能认定分辨率是唯一原因。阈值不合适也显著压低了 Macro-F1。

| 轮次 | 训练 BCE | 验证 BCE | Macro-AUC | Macro-F1，阈值 0.5 |
| --- | --- | --- | --- | --- |
| 1 | 0.36937 | 0.31430 | 0.74343 | 0.20434 |
| 4，最佳 AUC | 0.27761 | 0.32990 | 0.77518 | 0.23004 |
| 54，最后一轮 | 0.00213 | 1.10447 | 0.71899 | 0.31171 |

`last.pt` 确认 stale=50，因此是第 4 轮后连续 50 轮没有刷新 AUC 而早停。最终训练损失极低，但验证损失显著上升，AUC 从最佳值下降约 0.05619。第 54 轮 F1 高于第 4 轮并不能说明整体模型更好，因为 F1 受固定阈值影响。

1000 轮总周期使余弦衰减过慢：最后检查点学习率仍为 0.000992894074598754，约为初始值的 99.29%。本轮训练在明显衰减之前已经早停。较低学习率、较短且匹配实际训练时长的调度周期、适当正则化均值得独立对照，尚不能认定其中某一项必然提高分数。

## 分辨率检查

只读扫描全部 30,344 张训练影像和 1,422 张验证影像文件头。两个划分的原图长边中位数均为 3056，短边中位数均为 2544。现有流程等比例缩放并填充，不做中心裁剪；224 输入中，有效画面的短边中位数约为 186.47，长边为 224。若使用 512，有效短边中位数约为 426.22，输入像素总量约为 224 的 5.22 倍。

Ultralytics 的 YOLO26 分类预训练模型以 224 作为 ImageNet 评测尺寸，这不等于胸片任务的最优尺寸。[官方分类文档](https://docs.ultralytics.com/tasks/classify) 也允许调整输入和预处理。胸片分辨率研究发现，不同疾病对尺度的需求不同，某些精细征象受益于高分辨率，另一些更依赖大范围结构；更高分辨率并非所有类别都单调受益。[原始研究：Effect of image resolution on automated classification of chest X-rays](https://pubmed.ncbi.nlm.nih.gov/37547812/)

建议下一步做 224 与 512 的训练对照，从相同合规预训练权重出发、保留官方数据划分与 Study 聚合。512 可先以 batch=16 探测显存；该组合尚未在本次任务做容量测试。若希望维持名义更新批量 128，可用 nbs=128 做梯度累积，但 BatchNorm 仍按微批统计，所以不能宣称与 batch=128 完全等价。学习率、正则化和调度周期应作为独立因素比较，避免一次修改全部设置后无法归因。更改预测 imgsz 不能补回训练阶段丢失的信息，当前入口也要求训练与预测尺寸一致。

## 验证集复算与阈值

固定第 4 轮 best.pt，在完整官方 valid 的 1,422 张影像上 FP32 推理，batch=16、workers=3、不使用 TTA，按同一 Study 的概率均值聚合到 859 次检查。复算 Macro-AUC=0.775180129351788、Macro-F1@0.5=0.23003612994347772，与训练记录一致。

最佳权重 SHA-256：`0d4db2cc333658a10cacf8262fdf409f7343bcbac3610a22e5665dc341ed88b7`。

搜索目标是最大化验证 Macro-F1，而不是把阈值数值本身调到最大。判定使用 `Probability >= Gate`；枚举全部 8592 个概率断点及边界候选，在完全同分的候选中取较大的阈值。已经用独立的逐候选二值化算法核对统一阈值最优解。

| 统一阈值 0.5 | 0.230036 |

现有 predict.py 的 gate 接受单个数值，可填入 `gate=0.0684555247426033` 使用统一方案。逐类方案的完整数值保存在本机 summary.json 的 class_thresholds，顺序对应官方 ID 1–10；现有推理入口尚未接入阈值列表。本次仅完成诊断与阈值搜索，预测入口的配置保持原值。换权重、分辨率、TTA 或聚合方式后须重新估计阈值。

[赛事官网](https://www.ncccu.org.cn/index/Paper/case1.html) 明确允许填写类别 Gate，按 Macro-AUC 排名、同分比较 Macro-F1。[scikit-learn 官方阈值调优说明](https://scikit-learn.org/stable/modules/classification_threshold.html) 说明了默认 0.5 与指标最优阈值的区别，并强调使用独立于模型拟合的数据调阈值。测试集未参与本次分析。

## 对所引用诊断文字的修正

- 当前项目的 BCE 是多标签改造后的损失；Ultralytics 默认分类任务是单标签分类，不能把其 top-1/top-5、损失与当前项目直接等同。
- 11.7 GB 显存占用不能直接推出“显卡已满”或“绝不能增加 batch”。还需区分卡总容量、分配/保留显存、其他进程和阶段峰值；应该实测吞吐与剩余容量。
- 本项目是多标签任务，适合每类一个 2×2 混淆矩阵，分别观察 TP、FP、FN、TN；单标签 10×10 矩阵的“类别互相混淆”解释不直接适用。
- 当前训练代码原先没有自动生成混淆矩阵。本次分析脚本补充生成逐类矩阵，采用逐类最优阈值，不是原生单标签训练器的默认文件。
- “AUC=0.74 是正常起步”“几十轮后一定会提高”没有统一保证。本次最佳值第 4 轮已经出现，应依据具体曲线判断。

参数直接在 tools/analyze_training.py 的入口修改，每次运行使用新的 name。所有派生产物位于 outputs/analysis/，原始数据保持只读。

```powershell
uv run --no-sync python -m unittest discover -s tests -p test_thresholds.py
uv run --no-sync python tools/analyze_training.py
```

新增三项单元测试通过，覆盖与穷举搜索一致、同分概率、阈值边界、无效输入以及患者分组不泄漏。完整验证集分析运行成功。

- summary.json：权重哈希、配置、阈值、交叉拟合结果和图像尺寸统计。
- per_class.csv：逐类 AUC、阈值、Precision、Recall、F1、TP/FP/FN/TN。
